# 移植陷阱清单（Rust → Zig 重写用）

> 来源：ki（Rust）实现与多轮对抗审查中**实际踩过并在测试里钉住**的坑。每条是
> 「陷阱 → 不变量 → 验收」三段，语言无关，Zig 侧按自己的并发模型映射即可。
> 详细取舍见 `ki-acp-serve.md`、`ki-mcp-builtin.md`、`plugin-abi.md`。

## 1. ACP / 控制面

1. **串行分发是默认（官方 crate 亦然）**：读循环逐个 await 处理器，长任务会堵住
   cancel。不变量：prompt 处理器内**同步**抢在途守卫 → 把应答句柄移交并发执行 →
   立即返回；cancel 在读循环同步处理。验收：prompt 进行中发 cancel，必须打断。
2. **同 burst cancel**：lane 在 run 注册前（`acquire_run` 之前）会吞掉单次 abort
   （无在途运行）。不变量：宿主侧要么有「启动窗口 + pending-abort」，要么以
   100ms tick 重发 abort 直到接收。验收：prompt 与 cancel 零间隔发送，流必须被截断。
3. **标志顺序**：先抢在途（swap true）再清取消标记；反过来会清掉刚到的 cancel。
   空闲时的 cancel 必须是严格 no-op，不许杀掉下一回合。验收：空闲 cancel 后下轮正常完成。
4. **单活跃会话/进程**：事件 sink 或策略是进程级单槽时，第二个会话会抢走第一个的。
   不变量：并发 `session/new` 明确拒绝；或先做按会话仲裁。
5. **版本协商**：应答协商出的版本（不是回显）；能力声明与实现同真，声明是唯一
   闸门（禁止靠错误码探测对端支持）。
6. **stdio 纪律**：stdout 只跑协议、日志一律 stderr、收尾打一行原因+退出码。
   验收：管道里 grep 不到任何非 JSON 行。
7. **会话参数第一刀解析**：不认识的参数宁可响亮拒绝，不许静默忽略（`mcpServers`、
   `additional_directories` 都是这么定的）。

## 2. MCP / 连接生命周期

8. **孤儿进程**：官方 HTTP/stdio 客户端的优雅关闭只收干净退出的 server，**孙进程
   会成孤儿**。不变量：unix 进程组 SIGTERM（pgid 还在手上时）+ Windows job object。
   验收：OS 级断言 server pid 与孙进程都消失。
9. **读路径无长度上限**：官方 client 的 stdio 读与 HTTP 读都可能无界。不变量：
   16MiB 总上限（Content-Length + 流式读取 + SSE 回复 + 长连流按事件计）。
   验收：分块响应与超大 SSE 事件都被拒。
10. **SSE 行终止**：裸 CR、LF、CRLF 都算行终止——只按 `\n\n` 重置计数会把长连流
    在 16MiB 后误杀。
11. **重定向与凭据**：只跟随同源重定向（跨源要拒绝且不接触目标）；URL 拒绝内嵌
    userinfo（那是 Basic 认证通道）；日志别打印完整 URL。
12. **404=会话过期**：自动重初始化后，**宿主侧订阅不会自动恢复**——必须自己重放
    （每 URI 一次、先装生命周期再放行首条通知）。
13. **订阅幂等**：对活跃 URI 再 subscribe 不许再发 RPC（拒绝重复订阅的 server 会
    因此丢订阅）；每次订阅轮换生命周期并清掉该 URI 旧队列；标记先于 RPC（握手中
    早到的通知不能丢）；server 拒绝要按期望 token 回滚。
14. **退订失败**：远端注册可能还活着 → 退役传输，下次重连时恢复**其他**订阅，
    被退订的 URI 仍可重新订阅。
15. **通知语义**：只把 `(server, uri)` 交给模型，**读取按需**（不要自动读全文注入）；
    同一 URI 合并、超限计抑制数；只在回合边界排干，绝不切活跑。
16. **连接随会话**：连接所有权跟会话走，不用全局静态表；每次 spawn/出网都记日志；
    env 白名单（provider 密钥不进 server）。

## 3. 权限门（强制，不是建议）

17. **「工具 ≠ 强制」**：本仓库原实现只提供 `permissions` 工具、**从未自动拦截**。
    不变量：强制执行只在工具调度前端的唯一收口。
18. **被治理者不能改规则**：暴露 grant/revoke 时，规则目标必须包含 action/rule
    （否则 deny `permissions(grant)` 永远匹配不上）；且该工具自身可被策略禁止。
19. **策略文件对 agent 只读**：write/edit/bash 等任何能落到策略文件路径的写入都拒
    （路径规范化后比较）。
20. **目标不能被非执行键遮蔽**：门外读 `value`、执行用 `command` 的错位可绕过——
    按工具的**执行键**取目标，额外键不参与放行。
21. **损坏策略**：fail-closed，但保留修复通道（read 与「写策略文件本身」放行）。
22. **作用域**：未受信项目的策略不生效；项目优先于全局；并行写策略用带序号的
    临时文件 + 原子替换。
23. 语义基线：deny 优先；无 allow 列表即放行；glob 匹配工具名/目标。

## 4. wasm / 插件层

24. **事件面不能挂在某一层**：把事件分发挂在「cdylib 会话存在性」上，会让
    「全 wasm、零 dylib」的安装**整条事件面失效**（计费/恢复/生命周期全死）。
    不变量：挂在「已安装插件集合」，与任何一层的有无无关。
25. **调用线程**：guest 用 WASI 时钟睡眠（对话框轮询）时，在带运行时上下文的线程上
    会 panic（`Cannot start a runtime from within a runtime`）。不变量：guest 调用
    放**普通线程**（不要用运行时的阻塞池）。
25b. **观察型事件分发不能等一个正在等用户的插件**：wasm 的调用锁在 guest 执行期间
    一直被持有，`ask_user` 会拿着它轮询用户答案；而 TUI 在打开对话框前先在**按键
    线程**上分发 `UiPromptStart`。观察分发若对忙碌插件阻塞就会死锁——对话框永不出现、
    Esc 失效（2026-10-18 实测挂起 36 分钟）。不变量：观察面（`dispatch_to_handlers`
    / lifecycle）走 `try_on_event`，忙则跳过；只有决定控制流的 claiming 面允许阻塞。
26. **能力模型**：声明归作者、授权归用户、执行归宿主；单 scope（FS 要么插件数据目录
    要么项目树，不能两者兼得——需要两者时说明这是设计缺口）。
27. **安装完整性**：SHA-256 sidecar（安装写、加载校验）；缺失警告但加载、不匹配
    跳过并报错。定性为完整性检测，签名另议。
28. **命名**：MCP 工具展开为 `{server}__{tool}`；插件工具撞名跳过并告警；工具名
    满足 provider 约束（`[A-Za-z0-9_-]{1,64}`）。
29. **`--no-tools` 等抑制开关**：被忽略的插件/server 要响亮告警，不许静默。

## 5. 工程与验证

30. **构建产物路径**：用重定向 target 目录的环境里，「按相对路径取产物」的测试会假红
    ——按构建工具报告的实际产物路径取，或先验产物再归罪代码。
31. **代理环境变量**：会劫持 loopback 测试（连接挂死）——测试要绕行 loopback。
32. **审查结论要实证**：本仓库多轮审查中出现过高置信度误判（「义务无测试钉住」被突变
    推翻；「握手硬拒非 V1」被探针证伪）。判定三桶：修复 / 驳回（带证据）/ 未验证
    （配额掉线的空结果**不算**通过）；高危结论必须有突变测试或探针复现。
32b. **恢复出的分支可能从孤立的 tool result 开始**：崩溃时若「带 tool_calls 的
    assistant 消息」没落盘、而 tool 结果落盘了，日志重建出的分支就以 `role: tool`
    开头——provider 一律 400，且该会话此后永久不可发送。不变量：provider 边界要
    丢弃「前面没有声明该调用的 tool result」（以及重复结果），只修「有调用没结果」
    是不够的。
33. **阈值变更**：上限/超时/额度的调整单独提交并写明新旧值与理由；删除任何文件/分支
    前先列清单取得许可。

## 6. 测试基线（最小集）

- cancel-during-prompt（含同 burst）、空闲 cancel 不污染下轮；
- MCP：进程树无孤儿（OS 级）、16MiB 上限、404 后订阅恢复、订阅幂等（记录 RPC 次数）、
  被拒退订后可重订阅；
- 权限：deny 拦截（含自改规则/直接写策略文件/参数键遮蔽三个绕过）、损坏策略的修复通道；
- 事件面：无 dylib 安装下 SessionStart/TurnEnd/SessionShutdown 仍到达插件。
